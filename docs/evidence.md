# gaishi の根拠: 「作業は英語、報告は日本語」は妥当か

最終更新: 2026-10-06 / 対象バージョン: 0.2.0

gaishi の設計意図は次の2点です。

- **H1 トークン削減**: 作業を英語で行うことで、日本語より少ないトークンで済ませる。
- **H2 性能向上**: モデルにとって支配的な言語(英語)で作業させることで、精度を上げる。

加えて、設計上の前提として **H3** を置いています。

- **H3 報告品質**: 最終報告だけを日本語にしても、ユーザー体験は損なわれない。

結論を先に書くと、**H1 と H2 は論文の裏付けがある(査読済みの会議論文と arXiv プレプリントが混在)が、効果の大きさは条件次第**で、すべてのタスクで効くわけではありません。H3 は直接の研究が少なく、設計判断に近い部分です。以下、論文ごとに「何が確認できたか」と「限界」を分けて書きます。

## 確認方法について

- 各論文は arXiv / ACL Anthology / OpenReview の実在を確認しました。会議名は、確認できたものだけ記載しています(確認できなかったものは arXiv と表記)。
- **本文を読んで数値を確認したもの**: Shi et al. (MGSM) の Table 3、Petrov et al. の Table 1。
- **アブストラクト(または公式ページの要約)を確認したもの**: それ以外すべて。本文の追試はしていません。
- 数値は論文の記載をそのまま引用しています。私による再計算や推測は「実測」と明記した箇所だけです。

## H1: トークン削減

| 論文 | 確認できた内容 |
| --- | --- |
| Petrov et al., [Language Model Tokenizers Introduce Unfairness Between Languages](https://arxiv.org/abs/2305.15425), NeurIPS 2023 | 同じ内容を英語と比べた日本語のトークン長の比(Table 1, FLORES-200): GPT-2/RoBERTa 系で **3.00 倍**、ChatGPT/GPT-4 の `cl100k_base` で **2.30 倍**。言語全体では最大15倍の差が出ると報告。 |
| Ahia et al., [Do All Languages Cost the Same?](https://aclanthology.org/2023.emnlp-main.614/), EMNLP 2023 | 従量課金の API では、トークン化の非効率な言語の話者ほど多く課金され、しかも結果は劣る傾向があると報告(22言語、アブストラクトの主張)。 |

**実測(非公式)**: 技術的な作業報告・エージェント指示・レビューコメントの3種類について、英語と日本語の対訳(筆者作成)を `tiktoken` で数えました。

| トークナイザ | 英語 | 日本語 | 日本語/英語 |
| --- | --- | --- | --- |
| `cl100k_base` | 167 | 427 | 2.56 |
| `o200k_base` | 167 | 318 | 1.90 |

**解釈と限界**

- 日本語は英語の約 **1.9〜2.6 倍**のトークンを使います。新しい語彙ほど差は縮みます(`cl100k` → `o200k` で 2.56 → 1.90)。
- 実測は3サンプルだけで、OpenAI 系トークナイザのみです。**Claude や Gemini など他社モデルのトークナイザでの数値は未検証**です。
- 削減できるのは、**エージェントが書く作業テキスト**(検索クエリ、メモ、サブエージェントへの指示、中間成果物)です。モデル内部の思考や、ツールが返す出力、最終報告の日本語は対象外です。
- skill 自体にもコストがあります。`SKILL.md` の本文は約 810 トークン(`o200k`)で、起動時に読み込まれます。**短い単発タスクでは削減分より読み込みコストが大きくなり得ます**。長い調査・多段のエージェント作業で効果が出ます。

## H2: 性能向上

### 英語で作業したほうが良いことを支持する研究

| 論文 | 確認できた内容 |
| --- | --- |
| Shi et al., [Language Models are Multilingual Chain-of-Thought Reasoners](https://arxiv.org/abs/2210.03057), arXiv 2022 | 日本語を含む10言語の算数問題(MGSM)で、**英語で推論する (EN-CoT) ほうが、問題と同じ言語で推論する (Native-CoT) より同等かそれ以上**。PaLM-540B・日本語の Table 3: Native-CoT **40.0** / EN-CoT **49.6** / Translate-EN **50.0**(英語問題は 62.4)。GPT-3 の日本語: 26.0 / 32.4 / 44.8。 |
| Etxaniz et al., [Do Multilingual Language Models Think Better in English?](https://arxiv.org/abs/2308.01223), arXiv 2023 | 5タスクで、モデル自身に英語へ翻訳させてから解く **self-translate が直接推論を一貫して上回る**。非英語のまま解くとモデルは能力を出し切れないと結論。 |
| Zhang et al., [Don't Trust ChatGPT when your Question is not in English](https://arxiv.org/abs/2305.16339), EMNLP 2023 | 英語以外のプロンプトでは、ChatGPT は意味解釈の少なくとも一部を英語の能力に頼っている証拠がある。英語以外で生成品質が大きく低下する。 |
| Wendler et al., [Do Llamas Work in English?](https://arxiv.org/abs/2402.10588), ACL 2024 | Llama-2 の内部で、概念表現は他言語より英語に近い。英語が内部のピボットとして働く。 |
| Huang et al., [Not All Languages Are Created Equal in LLMs](https://arxiv.org/abs/2305.07004), EMNLP 2023 Findings | 言語ごとに性能差があり、英語で考えさせる XLT プロンプトで改善する。 |
| Barua et al., [Long Chain-of-Thought Reasoning Across Languages](https://arxiv.org/abs/2508.14828), ICLR 2026 | 推論モデルでは、規模を上げると **En-CoT の性能は上がるが Target-CoT は遅れ**、差は数学など長い推論ほど広がる。 |
| Hofman et al., [MAPS](https://arxiv.org/abs/2505.15935), EACL 2026 Findings | GAIA、SWE-Bench など4つのエージェント系ベンチマークを11言語に翻訳。**英語から他言語に移ると性能と安全性が低下**し、翻訳された入力の量と相関する。 |
| Luo et al., [Lost in Execution](https://arxiv.org/abs/2601.05366), ACL 2026 | ツール呼び出しの失敗の主因は、意図の理解ではなく、**引数の値をユーザーの言語で生成してしまうこと**。対策を入れても英語水準には戻らない。 |

### 英語一辺倒を戒める研究(限界)

| 論文 | 確認できた内容 | gaishi への反映 |
| --- | --- | --- |
| Liu et al., [Is Translation All You Need?](https://arxiv.org/abs/2403.10258), NAACL 2025 | 英語への翻訳は標準的な NLP タスクで有効だが**常に最適ではない**。文化に根ざしたタスクでは**母語のプロンプトのほうが良い**。 | 日本固有の素材は翻訳せずに日本語のまま扱う節を追加(0.2.0)。 |
| Qi et al., [When Models Reason in Your Language](https://arxiv.org/abs/2505.22888), EMNLP 2025 Findings | 推論モデルに**思考の言語を強制すると、読みやすさは上がるが精度が下がる**。 | 内部の思考言語は制御しない、強制すると精度が下がり得る、と明記(0.2.0)。 |
| Ozaki et al., [Do LLMs Need to Think in One Language?](https://arxiv.org/abs/2505.21458), 2025 | 内部で言語を一貫させることは、翻訳・地理文化タスクの性能に必須ではなかった。モデルは終盤の層で出力言語に合わせる。 | 「英語で考えるから強い」という機構の説明は断定せず、行動(書く言語)に絞った設計にした。 |
| Marchisio et al., [Understanding and Mitigating Language Confusion in LLMs](https://aclanthology.org/2024.emnlp-main.380/), EMNLP 2024 | 英語中心のモデルは、意図しない言語のトークンが混ざる「言語混乱」を起こしやすい。複雑なプロンプトと高い温度で悪化。 | 最終報告は全文日本語にし、英語や別の文字が混ざらないよう明記(0.2.0)。 |

### 総合判断

- 「英語で作業する」ほうが同等以上の性能になることは、複数の独立した研究で一貫しています(Shi, Etxaniz, Barua, MAPS)。
- ただし、**多くの研究は数学や NLU の標準ベンチマーク**で、PaLM や GPT-3 など**古いモデル**が中心です。最新のモデルでは差が縮んでいる可能性が高く、**現行のコーディングエージェントでの実測値ではありません**。
- 日本語の知識が本質のタスク(日本の法律、日本語の校正、ローカライズなど)では、英語化はむしろ不利です。

## H3: 最終報告だけ日本語にする

- 「英語で作業し、母語で報告する」構成そのものを直接評価した論文は、今回の調査では**見つかりませんでした**。
- 間接的な根拠: 非英語の思考を強制すると精度が下がる(Qi)ため、**作業は英語のまま、最後にだけ日本語化する**ほうが、全体を日本語化するより安全と考えられます。
- 懸念: 翻訳による情報の欠落、日本語出力への言語混乱(Marchisio)。これらは報告ルールで緩和しています(結論先出し、固有名詞・コード・エラー文は原文のまま、全文日本語)。**緩和策の有効性は未検証**です。

## この調査で見つけて、skill に反映した修正(0.1.0 → 0.2.0)

1. **ツール引数は英語/言語中立のまま**(Luo et al.): 引数を日本語に訳すと失敗の主因になる。
2. **日本語が本質の素材は翻訳しない**(Liu et al.): 日本固有の検索、対象テキスト、曖昧な業務用語は原文を残す。
3. **思考言語を強制しない**(Qi et al.): 制御できないと明記し、強制による精度低下を注意書きに追加。
4. **最終報告は簡潔に、全文日本語に**(Petrov / Ahia, Marchisio): 日本語は約2倍のトークンを使うため、過程ではなく結論を報告する。言語混乱を避ける。

## 未検証・今後の課題

- Claude / Gemini など他社トークナイザでのトークン比。
- 現行モデルのコーディング・調査タスクで、gaishi あり/なしの **A/B 評価**(正答率、総トークン、日本語報告の品質評価)。数十タスク規模で、同一モデル・同一温度、各条件を複数回実行するのが最低ライン。
- 日本語レポートへの翻訳による情報欠落の測定。
- 既存の skill 起動コスト(約 810 トークン)を回収できるタスク長の見積もり。

これらは今回のセッションでは実施していません。結果が出るまでは、**「論文の傾向からは妥当だが、gaishi 自体の効果は未測定」**と読んでください。
